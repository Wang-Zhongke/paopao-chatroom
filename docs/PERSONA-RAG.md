# Persona RAG：当前知识库

泡泡 Skill 提供思考和表达原则；RAG 从原始公开视频字幕中检索历史材料，帮助回答更贴近可核对的表达。检索是增强层，未命中或索引不可用时仍可正常聊天。当前采用本地 BM25 索引，不依赖独立向量数据库服务。

## 数据范围

| 项目 | 当前数量 |
|---|---:|
| 本地归档的视频机器文本 | 353 份，约 121.9 小时 |
| 通过质量检查并进入检索 | 345 份 |
| 暂隔离、等待校对 | 8 份 |
| 可检索单元 | 1,794 个 |
| 其中精标完整问答 / 观点定位 / 原始讨论段 | 1 / 1,386 / 407 |

运行时**只读取一个** `data/rag/index.json`，约 25 MiB。构建该索引时合并两类输入：

- `data/rag/units.json`：7 个经过人工划定边界的单元；保留它们的标注，不重复自动生成。
- `data/rag/auto-units.json`：从公开来源卡和本地原字幕加工出的 1,787 个单元，由 `rag:prepare` 重建。

它们是同一知识库的两种标注来源，并非旧版库与新版库同时参与回答。7 + 1,787 = 1,794；索引构建后统一检索、排序和过滤。扩库前的索引只在本地研究归档中，不进入公开仓库或运行时。`persona-rag-v0.1` 是当前实现的版本标识，不表示只使用早期少量素材。

来源卡的标题、判断和时间定位用于找到原字幕，不作为泡泡老师的逐字原话。机器字幕尚未全部人工核音；原始讨论可能包含来电者和其他说话人，所以不能把整个片段当成老师独白。只有 1 个单元被精标为完整问答，不能把 1,794 个单元宣传成 1,794 个完整连麦案例。

## 本地构建与检查

拥有本地原字幕和来源卡后，在连麦室根目录运行：

```sh
pnpm rag:prepare      # 加工来源卡和字幕，不调用模型
pnpm rag:build        # 合并精标与派生单元，重建唯一的运行时索引
pnpm rag:eval         # 五类基础检索场景
pnpm rag:eval:full    # 来源覆盖、原文一致性、隔离与八题检索检查
pnpm rag:debug -- "泡泡以前讲过输出型学习吗？"
```

更新来源卡或字幕后先 prepare 再 build。加工失败不覆盖旧清单，原文哈希不符时拒绝使用过期标注；构建采用原子替换。服务按索引文件变动重新加载，无需重启。公开仓库包含精标清单、来源卡和处理程序，**不包含完整原字幕、派生清单或生成的索引**；仅下载公开仓库不能重建同一份 345 视频索引。无索引时自动回退到 Skill 回答。

## 请求时如何使用

只有相关问题才触发检索。从最多 40 个候选中做相关性过滤、去重与来源限制，最多把 3 条证据加入上下文，累计不超过 24,000 字符。未检索到、相关性低、读取失败或关闭 `RAG_ENABLED` 时，不影响正常回答。检索本身不调用模型；选入的证据会增加模型输入量。阈值集中在 [检索配置](../lib/rag/config.ts)。

本地验收：五类基础场景 5/5、八项新增检查 8/8；345 份可用视频的全文覆盖及原文哈希检查通过，8 份弱证据未入索引。这验证了材料覆盖和检索边界，不证明每轮生成回答准确，也不构成全量人工语义审查。中文关键词检索对同义改写仍可能漏召回。
