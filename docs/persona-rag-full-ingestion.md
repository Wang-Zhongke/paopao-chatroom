# 全量素材入库（2026-09-23）

## 实际范围

| 项目 | 数量 |
|---|---:|
| 本地原视频字幕，完整归档 | 353 份 |
| 通过既有文本质量检查并进入检索 | 345 份 |
| 弱证据隔离，等待校对 | 8 份 |
| 可检索原字幕 | 237,829 条，约 392 万字符（含编号） |
| 检索单元 | 1,794 个 |
| 已有精标完整问答 | 1 个 |
| 观点定位单元（含原有 6 个） | 1,386 个 |
| 完整视频／长视频原始讨论子段 | 407 个 |

单元之间存在原文重叠，不能把单元正文长度相加当作去重语料量。索引约 25 MiB，正文来自原字幕，不是来源卡总结。全部 353 份原文另存 `data/rag/corpus.jsonl`，含被隔离的 8 份。

这次由 Codex 编写和执行本地处理流程，复用原有 353 张研究来源卡的论点、字幕定位和质量限制；没有调用 DeepSeek 或其他额外模型 API。不是把 353 份原文重新逐句人工阅读／音视频核验，也没有新增自动说话人识别。

## 如何加工

1. 检查完整字幕编号、文件哈希和既有质量标记。
2. 从来源卡的“主要判断与推理”提取观点及其字幕范围；正文取首尾引用之间的连续字幕，保留中间背景，不拼接孤立金句。
3. 另保留整份视频正文。只有超过单元上限的长视频才按来源卡议题起点或明确话题转折分段；不能找到合适边界就报错，不机械按 token 切断。
4. 长视频子段统一标 `transcript`，不冒充完整连麦或已经确认说话人的纯观点。407 个原文单元构成每份可用视频的无遗漏、无重叠覆盖。
5. 8 个跨距过长的观点定位不单独建观点单元；其原文仍完整保留在对应视频单元中。每项原因在加工报告中。
6. 原有 7 个精标单元继续保留。所有新增单元标 `source-card-boundaries-audio-unverified`，与原有文本边界检查区分。

来源卡也是研究转述，可能存在边界或判断错误。`claim`、`title`、`context` 用于定位，回答必须核对 `content`，不能把这些概括当本人原话；原始讨论也可能包含来电者、第三方播放和宣传。

## 更新与验证

```sh
# 纯本地，不加载密钥、不调用任何模型接口：
pnpm rag:prepare
# 从原字幕和清单重建检索索引：
pnpm rag:build
# 原有五类问题回归：
pnpm rag:eval
# 全量原文一致性、覆盖、质量隔离和新增八题检索检查：
pnpm rag:eval:full
```

需要本地原字幕及研究来源卡。公开源码包没有原字幕，不能仅下载公开包就复现这 345 份全文索引；缺失索引时聊天继续以 Skill 回答。

更新来源卡或字幕后先 prepare 再 build。prepare 失败不替换已有自动清单；原文哈希不符时 build 拒绝使用过期标注。构建使用原子替换，服务按文件变更自动加载索引，无需重启。失败时旧索引保留。

## 检索与上下文成本

扩库后本地候选池从 Top 12 增到 Top 40，再按原有绝对相关性条件筛选；次选证据还要求分数至少达到首条的 75%。相近相关度（差不超过 0.03）时优先较短的包含关系片段，且不同时发送同来源的重叠字幕。

每轮仍最多 3 条证据、每视频最多 2 条、序列化单元累计最多 24,000 字符；没有把全部素材发给聊天模型。完整原文单元较长，实际每轮 token 仍取决于命中材料；本轮只测检索，没有新增真实回答 API 用量测试。

索引文件读取预算从 20 MB 调整为 64 MiB，以容纳全量索引；这只是本地文件安全上限，不是模型上下文上限。检索超时和 Fail-Open 不变。

## 本地文件与分发

- `data/rag/units.json`：原有 7 个精标单元。
- `data/rag/auto-units.json`：本地来源卡派生清单。
- `data/rag/index.json`：运行时索引。
- `data/rag/corpus.jsonl`：全部原文与质量信息。
- `data/rag/ingestion-report.json`：覆盖、隔离及单元跳过原因。
- `.local-archive/persona-rag/full-eval-latest.json`：本轮完整性与检索检查结果。
- `.local-archive/persona-rag/pre-full/`：扩库前的索引和清单备份。

原文、派生清单、索引和本地报告已加入 Git 忽略并排除公开发行包。加工和验证脚本可以公开。

## 限制

- 8 份弱证据未启用，不虚报 353 份全部可供回答。
- 目前仍只有 1 个精标的独立完整问答；其他连麦内容已可检索，但按原始材料保留，未全部拆成带可靠说话人标签的 QA。
- 中文关键词检索的同义改写召回有限。例如“敢学、愿意学和以教代学”组合问法在初测未命中，而具体问“以教代学为什么能暴露知识缺口”能命中。没有证据时正常回答。
- 检索测试验证预期来源进入上下文和边界条件，不证明最终回答准确性或人物还原度；没有做全量人工语义审查或新一轮真实 LLM 回答评测。

## 本轮验收结果

- 原有五类检索场景：5/5 通过。
- 新增六个主题来源检查、一个无关事实查询、一个闲聊：8/8 通过。
- 345 份可用视频的全文覆盖、原文哈希、逐单元内容一致性：通过；8 份弱证据未进入索引。
- 19 项单元测试、4 项公开打包检查、TypeScript 检查及 Next.js 生产构建：通过。
- 本机一次冷加载约 434 ms，已缓存检索约 3–9 ms；这是本次本机测量，不是性能保证。
- 新增八题的证据上下文为 0–20,323 字符，均在现有 24,000 字符预算内。未调用真实聊天模型，未测最终回答 token 用量。
