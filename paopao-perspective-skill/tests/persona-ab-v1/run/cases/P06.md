## 问题

我在学AI转型设计，刚花两周把一个工作流工具学熟，又出了更容易的新工具。是不是应该先把旧工具彻底吃透、证明没白学，再换下一个？作品集到底该体现什么？

## Skill ON（盲标签 X）

你这个问题问反了。你现在纠结的是“要不要把旧工具吃透”，但真正的问题是你把工具跟能力绑在一起了。这两个东西根本不是一回事。

你把“学了两周”当成了投资，“换工具”当成了割肉。可你想想，两周时间你到底买到了什么？你买到的是“这个工具怎么用”的操作记忆，这个东西本来就按季度折旧，明天出来一个更顺手的，它的市场价值当天就掉一截。你以为吃透旧工具是在保住沉没成本，其实你是在给一台正在过期的机器加时。

谁会为你“把旧工具彻底吃透”付钱？没人。客户要的是你把一个具体问题解决掉，老板要的是一个能出结果的人，招聘方要的是你能不能在三天内把新工具接到业务里。他们不会站在你身后看你拧了几百个小时的螺丝。工具决定的是速度，不是你去哪儿、干什么、验收标准是什么。这些东西你想不清楚，换十个工具也还是原地打转。

所以工具该怎么学？就一个原则：任务驱动。你现在手上有没有一个高频、重复、规则清楚的真实活儿？有，就用它去跑，旧工具跑通了就留着当基线，新工具来了就对比一下它把哪一段成本打下来了，快了多少、错在哪儿、值不值得切。跑完你就有数据、有案例、有判断。没有真实任务，你“吃透”的只是一个玩具，换不换都无所谓。

再说作品集。作品集最忌讳的就是“工具熟练度展览”。放一堆漂亮图，写“熟练使用 XX、YY、ZZ”，这种东西招聘的人三秒划过去，因为它回答不了他心里那个问题：这人能解决什么问题，值多少钱。

作品集要体现的是三件事。第一件，你面对的是一个什么样的真实问题，谁被卡住了，不解决会损失什么。第二件，你怎么判断该用什么方法，中间做了哪些取舍，为什么没选另一条路，失败了什么地方。第三件，结果是什么，从哪个基线到了哪个结果，这个结果能不能被验证、能不能迁移到别的场景。

你如果是设计师转 AI，最强的作品集不是“我会 AI 生图”，而是“我用 AI 把一个设计流程的某一段从 X 变成 Y，省了多少时间/多少钱，中间踩了哪些坑，这套判断换个行业还能不能用”。工具的名字最好一行带过，因为它明天就变，你的判断路径和结果才是别人看完能记住的东西。

现在回去看看你那个两周的工作流。它帮你解决哪个真实问题了？有没有真人在用、在评价、在付钱？如果没有，那你不是该纠结换不换工具，你是该先找个真活儿让它跑起来。跑起来之后你会发现，工具出新的根本不是坏事，那是你作品集里一条新对比数据。

## 模型自行模拟 OFF（盲标签 Y）

别急，你这个问题表面上是工具选择，实际上是个很典型的"沉没成本陷阱"。

先说工具。你花两周学的东西，下周就被新工具替代，这不是你的问题，是这个行业的常态。你要证明的不是"我没白学"，而是"我能快速迁移"。真正值钱的从来不是你熟练操作某个软件，而是你理解工作流背后的逻辑——节点怎么连、数据怎么流、什么环节能自动化、什么环节必须人工判断。这些东西换十个工具都通用。

所以我给你的判断是：**旧工具够用就行，别追求吃透。** 你要练的是"半天上手一个新工具"的能力，而不是"把某一个工具用到极致"。前者是转型的核心竞争力，后者是打工思维。

再说作品集。这是你真正问对的问题。

作品集要体现的不是"我会用多少工具"，而是**你能不能用AI解决一个真实的、具体的、别人也能感受到的问题**。

举个反例：很多人作品集里放"我用XX工具做了个自动化流程，效率提升300%"。这没有说服力，因为读者不知道你自动化了什么、为什么难、300%怎么算的。

正确的做法是：选一个你或你身边人真实遇到过的痛点，展示你**怎么定义问题 → 试了哪几条路 → 为什么最后选这条 → 中间踩了什么坑 → 最终的方案长什么样**。工具只是这个叙事里的道具，观众要看的是你的思考路径。

一句话：作品集卖的不是工具熟练度，是你解决问题的思路。工具会过时，思路不会。
