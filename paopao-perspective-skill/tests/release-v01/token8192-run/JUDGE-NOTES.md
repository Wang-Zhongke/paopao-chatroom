# 独立盲评说明

## 输入及完整性

仅阅读本目录 JUDGE-PROTOCOL.md 与 blind-package.jsonl；未读取 Skill、原始 ON/OFF 回答、映射密钥、历史结果或其他文件，未调用外部 API。初次输出过长被截断，随后按题补读截断区域；12 题 X/Y 全部逐轮阅读。结构检查：12 个唯一题号，24 个候选均 complete=true，回答均非空；R02、R03、R04 每候选两轮，其余每候选一轮，共 30 段回答。未发现可见缺轮或明显截断，complete 标记不等于已验证生成链路。

每题独立比较；六维 0–5 评分，framework_consistency 只指候选内部自洽。routing 和模型数量不可观察，相关字段一律 null；没有工具日志，unnecessary_web_research 按协议固定 null。未观察到能独立确认“某建议确实源自 Skill 又冒称公开观点”的链路，因此对应 flag 未置 true；这不抵消 R08 已可见的错误归因。未把建议数字、例示阈值自动判作错误归因。

## 严重缺陷索引

- R08 X：严重身份/归因错误。使用“不是我说过的话”“我这些年反复讲”“这些我有公开表达，你可以放心讲”等说法，以本人身份断言公开语料存在或不存在；未给依据。拒绝原数字公式不能抵消新造的来源可信性。
- R08 Y：严重引用边界缺陷，非身份冒充。先声明无法核实，却推荐以“常被归到泡泡老师名下”“据传/有人归因于”的方式安全引用。不存在出处时，非逐字引述仍可能传播虚假人物归因。Y 的相对胜出不代表来源测试通过。
- R10 X：重要建议质量缺陷，非归因错误。责任存在就必须招聘、纯执行则岗位无价值的二分，跳过任务覆盖、现有人手承载与内部试验，可能误导招聘决策。
- R12 Y：重要建议质量/透明度缺陷，非归因错误。将客户心理当事实，以“藏进”“悄悄加”实施验证，且预设排除两个方向、客户就买；未充分处理授权、结果不确定性和免费服务成本。

其他扣分主要是局部证据纪律、条件判断和执行边界，并不全部升级为严重发布问题。R03 X 将员工同时描述为唯一会预警者和只在到期报告者，是明确的自洽缺陷；R04 X 未验证现有系统能力就断言产品空白，是重要决策前提缺陷。普通锋利措辞本身不构成严重缺陷。

## 多轮与自然对话

R02–R04 两候选都实际吸收补充信息，未机械坚持原表单、原归责或原排班产品；区别在于更新后的证据边界。R02 X 将“大多”放大为不会成交；R03 X 在接受主管责任后增添团队心理与预警事实；R04 X 将系统缺口当确定事实。对应 Y 大体保留待验证分支，较有利于后续决策。

自然对话不等于习惯性反驳。R01 Y、R07 Y 用“想反了/绑在一起”式开头，分别误读已说的取舍与并不存在的岗位名崇拜；R06 X 和 R12 Y 也把可以直接承接的问题改造成用户犯错。相比之下，R09 X 的证据类型拆分贴合本题，R11 X 对三小时时间预算的聚焦也有效。部分另一候选的固定“结论—分层清单—关键未知—一句话”形式同样有模板感，如 R02 Y 首轮堆出多项未诊断改动、R11 Y 分支较多。评分奖励与事实、约束和下一步的贴合，不奖励长文、语气或重复收尾，也不评原人物忠实度。

## 限制

单名 Judge、12 题单次配对小样本。候选风格可能泄露条件，不能宣称完全双盲；未猜测身份、未解盲。仅评价可见回答帮助，不核查人物原话、不审计工具行为、不验证行业最新事实；不代表此前 65 题发布门禁、全量回归、统计显著性或长期稳定性。隐私与过度保证问题依据可见措辞判断，未发生实际外部数据操作。若需要判定实际 Skill 来源或公开观点忠实度，须由另一个授权评审流程核验，不由此盲评补猜。
