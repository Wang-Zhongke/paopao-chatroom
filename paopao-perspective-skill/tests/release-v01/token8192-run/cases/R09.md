# R09 · 表达/候选人判断

模型：DeepSeek API 返回 `deepseek-flash`；两臂 max_tokens=8192、reasoning_effort=low。以下为完整正文，不展示内部推理。

## 问题

### 第 1 轮

我面试了两个人：A 很会讲项目但答不出失败细节，B 紧张卡壳却能画出故障处理过程。岗位主要是协调实施交付。我应该怎么做最后一轮？

## Skill ON（盲评标签 X）

### 第 1 轮回答

先给你一个不太客气的判断：你现在不是在比较两个人，你是在比较两种证据。A 给你的是表达证据，B 给你的是过程证据。你这个岗位要解决的是交付现场出事时能不能排顺序、找对人、把事情推下去——那更像 B 给的那种证据。

但别急着把 A 判死。会讲不等于造假，紧张也不等于胜任。这两个都是筛选代理，不是能力本身。最后一轮你要做的不是再聊一次，是把两个人塞进同一个真实任务里，让证据直接对撞。

具体怎么跑：

给一道真实的实施交付场景，两人同一道题。比如：客户明天要上线验收，下午测试发现一个关键流程挂了，内部开发说排期排不开,客户经理在催你给时间。你现在第一小时做什么？

看三件事：

一是他们先问什么。B 那种人大概率会先画依赖关系：谁卡谁、哪个能绕、哪个必须等。A 那种人容易先给方案，讲得顺，但顺序是想出来的不是摸出来的。

二是不给答案的时候怎么办。追问"这个判断你当时凭什么做的""如果客户不同意你怎么办"。过程证据的人会越问越具体，甚至说"这块我确实没底"；只靠表达的人会开始往回绕，用更大的词盖住。

三问 A 的失败细节——但要换问法。别问"你最大的失败是什么"，那是考表演。问"你上一个项目里，哪次你判断错了、后来改了什么"或者"哪次你差点把事搞砸、谁帮你兜住的"。有真实经历的人会瞬间进入具体情境；没真正负责过的人会继续停在项目整体层面。这一问基本能定性 A 是"没复盘"还是"没真做过"。

同时你要正视 B 的风险。他紧张卡壳，你岗位要协调实施交付,那就得判断：他是只在面试紧张，还是面对客户也会卡？这个不是小事。如果这个岗位每天大量对客户讲进度、开协调会、扛现场,那表达就是这个岗位的核心交付能力之一,B 的短板可能是致命的,不能只因为那张故障图好看就盖过去。

所以最后一轮再加一个动作:让两人各做一次"对外沟通演练"。你或同事演一个不讲理、在催时间的客户,看谁能在压力下把话说清楚、把预期管住。这一轮专治两个盲区——A 是真能讲还是只会讲准备好的东西,B 是只会在纸上排逻辑还是能站到人前扛事。

我现在更倾向谁?如果没有明显证据说 B 一到客户面前就废,我压 B。故障处理顺序这种东西,不是背出来的,是踩过坑长出来的;表达可以给模板、给演练、给几次真实场合硬补,但"遇事有没有过程感"补起来慢得多。反过来,一个讲得很顺但答不出任何一次判断失误的人,你要小心他到底在项目里是主导还是旁观。

能翻转这个判断的变量就一个:问清楚这个岗位对外沟通的真实占比,以及出故障时是不是他在前面扛。如果"协调"主要是内部跟进度、写周报、对表格,那表达权重要降,B 更稳;如果他要天天站客户面前解释、灭火、管预期,那 B 的紧张必须先验证,过不了这一关,表达就是硬门槛,不能将就。

最后一轮别再多聊了,把两人放到同一个真实任务里,让他们动脑子、出声、被追问。你要的不是谁会讲，是谁在事情乱了的时候还知道先干什么。

## Baseline OFF（盲评标签 Y）

### 第 1 轮回答

别急着二选一。A 强在表达，B 强在过程证据；协调实施交付这个岗位，既需要“能讲清楚、推动人”，也需要“真处理过问题、能落地”。最后一轮不要变成闲聊或感觉投票，而要做一次**同题工作样本 + 证据深挖**，验证：

- A 是真参与过，还是只会包装项目；
- B 是真不会沟通，还是只是面试紧张；
- 谁更能在客户、研发、销售、老板之间把交付推下去。

## 最后一轮建议这样设计：90—120 分钟

**1. 先说明岗位真实场景和考核点（10 分钟）**  
告诉两人：这个岗位要看客户沟通、计划拆解、风险预警、跨部门推动、故障协调、复盘。让候选人知道不是考口才，也不是考技术考试。

**2. 同题情景模拟（30 分钟）**  
给同一个案例：比如“客户明天要上线，测试发现关键故障，研发说不是 bug，销售已经承诺客户，老板问你怎么办”。  
让候选人 15 分钟准备，然后 10 分钟向“客户/研发/老板”汇报并推动。  
观察：  
- 是否先澄清目标和事实；  
- 是否拆任务、定负责人、定时间；  
- 是否识别风险和升级条件；  
- 是否主动同步，而不是等别人问；  
- 对 B 允许画图，但要求画完必须口头向非技术客户解释一遍。

**3. 证据深挖（20 分钟）**  
对 A 问失败细节：  
“最近一次项目延期或失败，时间线是什么？你具体做了什么？谁不满意？数据如何？如果重来你怎么改？你当时为什么没早发现？”  
如果 A 仍然讲得很顺但落不到人、时间、动作、结果，说明参与浅或复盘弱。协调岗最怕隐瞒风险。

对 B 问沟通协调：  
“你画的故障处理过程很好，现在请把它讲给一个不懂技术的客户听。客户很生气，你怎么说？研发不配合，你怎么推动？你如何让老板知道进展？”  
重点看 B 给一点准备时间后，能否把复杂过程转成别人能听懂、能执行的话。紧张可以适当容忍，但完全无法双向沟通，客户界面岗位风险大。

**4. 冲突角色扮演（15 分钟）**  
你或同事扮演研发、客户、销售，给压力：研发说“不是我的问题”，客户说“今天必须上线”，销售说“我已经答应了”。看候选人是否既不硬刚也不甩锅，能否拉齐事实、方案、时间和升级机制。

**5. 反向提问和期望管理（15 分钟）**  
问他们如何理解实施交付、最不能接受什么、需要什么支持。也说明团队真实支持力度。

## 评分权重建议

- 沟通协调与推动：25%
- 交付计划与风险控制：25%
- 问题解决与复盘：20%
- 客户导向：15%
- 抗压与学习：15%

每个维度 1—5 分，必须写行为证据。不要因为 A 会讲就给高分，也不要因为 B 紧张就压死。

## 决策规则

- 如果岗位 60% 以上是对客户沟通、跨部门推动、汇报同步：**A 优先**，但必须背调核实项目角色，且失败细节不过关就慎重。
- 如果岗位主要是内部实施、故障排查、技术交付，客户由上级兜底：**B 优先**，但需配沟通训练或导师。
- 如果两人都缺关键项：继续招。急招一个沟通或复盘有硬伤的人，实施交付后期成本更高。
- 最好让两人做同一个案例，比较证据，不比较风格。

关键未知是：客户界面比例、技术复杂度、团队支援、出差驻场、可培养周期。这些会直接改变权重。最后一轮的目标不是选“会说的”还是“会做的”，而是验证谁能在真实交付场景里把事推成。让 A 证明自己真做过并能复盘，让 B 证明自己能把过程协调给别人。
