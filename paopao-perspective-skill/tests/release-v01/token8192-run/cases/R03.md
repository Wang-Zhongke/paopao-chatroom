# R03 · 管理/多轮

## 问题

### 第 1 轮

我带四个人，有位同事每次延期都说需求改了。我是不是该换人？

### 第 2 轮

我刚核对记录，三个延期项目都是我临近交付加了需求，而且没有调整期限。

## Skill ON（盲评标签 X）

### 第 1 轮回答

你这句话里其实已经藏了一个没验证的结论：**他说“需求改了” = 他在找借口 = 该换人。**

先把这三步拆开。因为你真正要判断的不是他这个人行不行，是**需求到底改没改、谁改的、改的时候你在不在场。**

问你自己三个问题：

**第一，需求是不是真的改了？**

如果确实是业务方三天两头改，那这不是他的问题，是你的流程问题。你换掉他，换个人进来,面对同一个改需求的环境,照样延期。你只是把一个人换成了另一个人的磨合成本。这时候你要修的是需求锁定和变更流程，不是换人。

**第二，为什么另外三个人没拿这个当延期理由？**

两种可能。一种是他们也被改了，只是自己扛住了、或者没跟你报；另一种是他们负责的模块本来需求就稳。这两种情况下，你换他，等于用“谁叫得响谁有问题”来做管理判断，剩下三个人看着，会学会闭嘴,而不是学会解决问题。

**第三，他是事后解释，还是事前预警？**

这是最关键的分水岭。真需求变更的人，会在变更发生当天就跟你说“这个改动会让原计划往后两天”。一个有能力的人，是拿着风险来找你。每次都是延期之后才说“因为需求改了”——那问题不在需求，在**他没把风险提前暴露给你**，你在替他的不确定性兜底。

所以判断分岔：

- 需求确实乱 + 他也提前预警过 → 修流程，不换人。
- 需求确实乱 + 他从不预警 → 教他预警机制，给一次机会。
- 需求没怎么变 + 他反复拿这个说事 → 这才是要查他真实能力的信号，但也不是直接换，先查他到底卡在哪儿：是不会拆任务、不敢拒绝、还是执行力不够。

**你现在该干的，不是决定换不换人，是拿最近三次延期做一次复盘。** 列四列：需求变更的真实时间点、谁提的、他什么时候通知你的、他当时承诺的交付时间。填完这张表，答案自己就出来了——要么是你需求侧失控，要么是他预警机制缺失，要么是他真的在拿需求当挡箭牌。

换人是最后手段，代价是招人、磨合、剩下三个人的安全感。别用这么贵的手段，去解决一个可能一张表就能看清的问题。

### 第 2 轮回答

那这事就翻过来了。**该换的不是他，是你的流程；而且你差点因为自己造成的问题,开掉一个说实话的人。**

先把这笔账记清楚：三次延期，三次都是你临近交付加需求，而且没调期限。也就是说在你加需求的那一刻，延期就已经发生了，只是他到交付日才把它显性化。他不是延期的原因，他是延期的报信人。你现在要开掉报信的。

再往深一层看，他其实做对了一件很多人做不到的事：**他每次都如实说了真实原因，没背这个锅，没编一个体面的理由糊过去。** 你团队里另外三个人面对你的临时加需求，是怎么处理的？两种可能，都得查：

一种，他们也被加了，但自己加班、压质量、砍测试扛过去了，你没看见。那是你在悄悄消耗他们的健康和交付质量，只是没爆出来。

另一种，他们负责的模块你没加需求。那说明你加需求的习惯是随机的，谁被你盯上谁倒霉。

**你如果按原来那个念头换掉他，会发生什么？** 剩下三个人会立刻学到一课：如实说“因为老板加需求所以延期”是要被换掉的。以后他们只会闭嘴，然后在交付日给你一个更烂的东西。你把团队里唯一一个会预警的人清理掉，换来一个安静的、你不知道什么时候会炸的团队。

现在动作很清楚，三件事：

**第一，需求变更必须有对价。** 以后你加需求，当场二选一：要么期限往后推，要么从原范围里砍掉等量的东西。不能你加、他扛、期限不动。这条定下来，写进你们的协作方式里。

**第二，给他正名。** 单独跟他说清楚：这三次延期是我加需求造成的，不是你执行的问题。这句话必须说，不然他心里那笔账还在，你团队的信任也回不来。

**第三，顺手教他一手。** 他也有可以更好的地方——他不该等到交付日才告诉你延期，他应该在你加需求的那一刻就说：“可以加，但交付得往后三天，你选。”这是把决策权还给你，而不是到期了通知你。这个能力他要是补上，你团队以后就顺了。

所以你看，这根本不是换不换人的问题。**你差点用一次招人、磨合、团队信任的代价，去修一个你开会时就能修掉的习惯。** 先去把那条变更规则立起来。

## Baseline OFF（盲评标签 Y）

### 第 1 轮回答

先给结论：**仅凭“每次延期都说需求改了”，现在不该直接换人。**  
更准确的判断是：先分清这是**系统问题**（需求管理混乱）还是**个人问题**（他不预警、不澄清、不担责）。  
如果是系统问题，换人大概率没用，新人来了一样会说“需求改了”；如果是个人问题，且给过机制和辅导仍不改善，才该考虑换岗或替换。

### 先看三种可能
1. **需求真的频繁变更，且没有变更流程**  
   这是你的流程问题，不是他的问题。需求方随口改、没有冻结、没有影响评估，谁做都会延期。

2. **需求模糊，他没有在开工前澄清**  
   他把“没问清楚”变成“需求改了”。这是能力和工作习惯问题，可以辅导。

3. **延期后拿需求变更当借口，且从不提前预警**  
   这是绩效和责任问题。专业做法是：变更一发生就重估、同步影响、给方案，而不是到截止日才说延期。

### 你现在该做三步
**第一步：取证，不要凭感觉。**  
拉最近3次延期，按时间线记录：  
- 原始需求是什么？何时确认？  
- 需求何时改？谁提的？有没有记录？  
- 他何时知道变更？何时告诉你？  
- 变更影响多少人天？他有没有给替代方案？  
- 其他三个人是否也遇到同样变更？

**第二步：一对一，不贴标签。**  
可以这样说：  
“过去三次延期，我想复盘事实，不追责。请你按时间线写清楚：需求何时变、谁确认、影响多少、你何时知道、何时同步、做了什么补救。以后需求一变，你要立刻同步新的完成时间和风险；如果会延期，至少提前两天告诉我，并给选项：砍范围、延期、还是加资源。”

**第三步：给机制，再观察。**  
四人小团队不用太重，但要有：  
- 需求基线：开工前确认范围。  
- 变更必须书面/工单确认，不能口头改。  
- 变更后必须做影响评估和重排期。  
- 每周一次风险同步，延期提前预警。  
- 给合理缓冲，不要把排期压到不可能。

观察1—2个迭代，或30—60天。看指标：提前预警率、变更影响评估及时性、按期交付率、需求澄清质量。

### 什么时候才该换人？
满足这些条件再考虑：  
- 需求变更并不频繁，或别人能处理，只有他反复延期；  
- 机制清楚后，他仍不提前预警、不做影响评估、不改进；  
- 已经一对一辅导、甚至PIP绩效改进，仍无改善；  
- 他的延期对客户、团队或业务造成实质影响；  
- 你算过换人成本：四人团队换一个等于少25%产能，招聘和上手还要1—3个月。

如果只是需求乱，先换流程；如果流程清楚了人还不行，再换人。  
所以我的判断是：**现在不换，先验证。系统问题修系统，个人问题给改进机会，无效再换。**  
如果你能补充最近三次延期的具体经过、需求变更记录、其他三人的表现，我可以帮你更明确地判断。

### 第 2 轮回答

这个信息很关键，我要修正上一轮判断：**现在不该换人，该换的是你这边“临近交付加需求、却不调期限”的做法。**  
从你核对的结果看，同事说“需求改了导致延期”，不是找借口，至少这三次是事实。你加需求、不调期限，等于单方面改了交付条件，却仍按原期限考核他，这在管理上不成立。

### 为什么换人不解决问题
四人团队，换掉一个人等于少25%产能，招聘和上手还要1—3个月。更关键的是：**如果新的人来了，你还是在临近交付加需求、不调期限，他一样会延期。**  
到时候团队学到的不是“要负责”，而是“别提前说，拖到截止日再说”。这对你更糟。

### 你现在该做的五件事
1. **先一对一澄清责任，别让他背锅。**  
   可以说：“我核对了三个延期项目，主要是我临近交付加需求，又没调期限。你说需求改了导致延期，这个判断是对的。接下来我会把变更规则定清楚。”

2. **复盘三个延期项目，做业务取舍。**  
   逐个问：这个新增需求当时必须做吗？如果不做会怎样？能不能放到下一版？现在还要继续加吗？  
   已经延期的项目，要和需求方/上级对齐：是延期、砍范围，还是加资源。**不要默认让团队加班解决。**

3. **建立变更铁律：范围、时间、资源，动一个必须动另一个。**  
   临近交付加需求，只有三个选项：  
   - 延长期限；  
   - 砍掉等量原范围；  
   - 加资源或明确加班补偿。  
   而且必须由你书面确认，不能口头说“这个也加一下”。

4. **设需求冻结点和变更窗口。**  
   比如交付前3—5个工作日冻结需求；冻结后新增必须走变更确认。  
   你可以用一个模板：  
   “新增X，影响Y人天，风险Z。选择：A延期到D；B砍掉原范围E；C加资源。请确认。”  
   没有这个确认，不进当前版本。

5. **继续要求他提前预警，但分清主次。**  
   他仍应做到：一有变更就同步风险、重估时间、给方案，而不是到截止日才说。  
   但这次延期的主因是你的变更决策。流程修正后，如果他仍然不预警、不沟通、质量差，那才是他的绩效问题。

### 什么时候才考虑换人
- 需求变更并不频繁，别人能处理，只有他反复延期；
- 变更规则清楚后，他仍不提前预警、不做影响评估、不改进；
- 除延期外，还有质量问题、协作问题、态度问题；
- 你已一对一辅导并给过改进期，仍无效。

### 一句话结论
**这三次延期，先别换人。你该做的是向团队修正归因，建立变更规则，重新排期和取舍。**  
如果你曾在团队里暗示过他“找借口”，需要尽快澄清。否则你会失去的不只是他的信任，而是整个小团队对你排期承诺的信任。
