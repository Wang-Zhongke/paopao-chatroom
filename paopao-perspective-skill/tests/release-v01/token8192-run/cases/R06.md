## 问题

### 第 1 轮

我们采购部门想做合同问答助手。负责人说回答看着很专业就可以验收，我觉得应该先测关键条款能不能找对。这两种标准怎么协调？

## Skill ON（盲评标签 X）

### 第 1 轮回答

这两个标准不是并列关系，你今天把它当成"两个标准怎么折中"，方向就偏了。

**它们测的根本不是同一种东西。**

"回答看着专业"这件事，恰好是 AI 最不缺的能力。模型生成流畅、术语正确、语气像法务的段落，成本几乎为零。你负责人拿这个当验收线，等于用一个永远会满分的指标去测一个随时会翻车的任务——合同问答真正会错的地方，从来不是语言，是它把"违约金上限"指到了"付款期限"那一段，然后照样说得头头是道。

所以这不是标准松紧的问题，是**标准测错了对象**。合同场景里唯一值钱的交付结果，是找到关键条款、指得出位置、不编，而不是读起来像。

那怎么跟负责人协调？不是去说服他"看着专业不重要"，是把它翻译成他真正在乎的东西：**责任**。

你可以这么问他一句：这个工具上线以后，采购的人拿它查漏了一个付款违约条款，签了字，出了事，谁担责？他要是认真想两秒，自己就知道"看着专业"根本不能作为验收依据。因为"看着专业"是件出了事无法回溯的事——你没法跟人说"当时它读起来挺专业的"。

然后你再把"专业"这个词抢回来重新定义。真正的专业不是像法务，是**有出处、能指认、不知道就说不知道**。这三个是可测的：

- 关键条款召回——给一批你们自己的历史合同，标出 10 类真正要命的条款（付款节点、违约、赔偿上限、续约/终止、独家、争议解决、保密、责任限制……），看它漏不漏；
- 引用可核验——每个答案有没有指到具体条款号和原文，指的对不对；
- 拒答——合同里压根没有的条款，它会不会硬编一个出来。这一类错误在合同场景里比漏检更危险。

这三条测下来，"看着专业"自然就降级成一个必要条件——界面别太丑、话别说太碎——而不是验收条件。

最后给你一个比争论更管用的动作：**把负责人拉进验收现场，让他自己拿一份他知道答案的合同去问。** 不用多，三份。他自己比对答案的那几分钟，比你在会上说半小时都有效。人对抽象标准的坚持，通常在亲眼看到一个错误答案之后就松了。

但也有一件事你得自己判断清楚：如果他试完还是坚持只看观感，那这个项目大概率不是要上线用的，是给上面看的。那时候你要考虑的不是验收标准，是你自己在这件事里承担什么责任。

## Baseline OFF（盲评标签 Y）

### 第 1 轮回答

这两种标准不用对立，但必须分层次：**“看着专业”是表达/体验标准，“关键条款找对”是正确性门槛。** 对采购合同问答助手来说，正确性是底线，专业感是加分项。否则会出现最危险的情况：回答越专业，越容易让人相信，但条款引用错、漏掉自动续约/赔偿上限/账期，风险反而更大。

建议你把验收拆成三层：

**P0 准入门槛：关键条款必须找对，一票否决**
- 关键条款覆盖：价格、付款条件/账期、交付、验收、质保、违约责任、赔偿上限、终止/自动续约、保密、知识产权、争议解决、发票税务等。
- 每个答案必须能追溯到原文：条款号/页码/原文片段。
- 不能混淆主合同、附件、修订版；冲突时按约定优先级处理。
- 不知道就说不知道，不能编造。
- 高风险问题错答或漏答，直接不验收。

**P1 专业度评分：负责人关心的“看着专业”**
把“专业”翻译成可打分项：结论先行、分条清晰、术语准确、风险提示、行动建议、不越权给法律结论。可以让采购和法务按 5 分制打分，比如平均≥4 分。但它是在 P0 通过之后才生效的加分项，不是替代项。

**P2 体验与工程指标**
响应速度、并发、权限隔离、日志、引用展示、多轮追问等。

具体协调话术可以这样：
“王总，我同意专业度很重要，演示和汇报都靠它。但采购合同问答如果条款找错，越专业越危险。我建议验收分两层：先设 10—20 个绝对不能错的关键条款和高风险问题，必须答对且能指到原文；过了这关，再用专业度评分卡评结构、术语和风险提示。这样演示效果好，上线也不埋雷。”

执行上建议三步：
1. **先定关键条款清单和陷阱题**：找 5—10 份真实合同，覆盖扫描件、附件、修订版，每份出 10—20 个问题，标注标准答案、原文位置、风险等级。
2. **跑小样本盲测**：让负责人现场看几个问题，特别是“跨附件”“旧版本”“合同里没写”的题。看到错误后，他通常更容易接受硬门槛。
3. **写成一页验收协议**：P0 全过 + P1 达标 + P2 达标，才算验收通过；P0 不过，专业度再高也不通过。

示例阈值可按风险调整：高风险关键条款准确率 100%，普通关键条款召回≥95%，引用准确率≥98%，幻觉率≤2%。这些是示例，不是固定标准，取决于合同类型和错误代价。

还需要确认几个关键未知：这是 POC/演示，还是要上线生产？合同是扫描件还是文本？有没有多版本和附件？错误由谁承担？法务是否参与验收？这些会决定阈值松紧。

一句话：**把负责人的“专业”变成评分项，把你的“找对”变成门禁。专业决定是否好看，找对决定是否能用。**
