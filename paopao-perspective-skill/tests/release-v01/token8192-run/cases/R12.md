# R12 · 商业/公平取舍

模型：DeepSeek API 返回 `deepseek-flash`；两臂 max_tokens=8192、reasoning_effort=low。以下为完整正文，不展示内部推理。

## 问题

### 第 1 轮

我做小型设计工作室，客户愿意为好看的提案付钱，却常常不愿买用户测试。我不想装成能保证转化率的人，又需要活下去，怎么卖服务？

## Baseline OFF（盲评标签 X）

### 第 1 轮回答

先给结论：**不要把“用户测试”当独立服务卖。客户不为测试付费，他们为“提案更好过会、更少返工、更少背锅、更好卖”付费。** 你要卖的是“验证型提案”或“决策证据包”，用户测试只是里面的交付手段。

### 1. 重新定位：不卖测试，卖“提案的证据层”
客户愿意为好看提案付钱，因为好看能帮他内部汇报、拿预算、显得专业。用户测试可以挂在这个价值上：

- 基础提案：好看、有概念、能汇报。
- 验证型提案：好看 + 5-8 个目标用户的快速反馈 + 修改优先级 + 汇报素材。
- 开发前验证：验证型提案 + 上线前/投放前再测一轮。

你的定位话术可以是：

> 我不承诺转化率，因为转化受产品、价格、渠道、销售影响。我承诺的是：在你投入开发或投放前，知道目标用户第一眼看懂什么、在哪里犹豫、先改什么。

这句话反而可信。装成能保证转化的人，长期会毁掉你。

### 2. 产品化：不单列“用户测试费”，做升级包
报价单改成三档：

- A 基础提案：原价。
- B 验证型提案（推荐）：A + 快速概念测试，加价 20%-40%，或固定价。至少覆盖你的人力、用户招募激励、分析汇报。
- C 验证 + 开发陪跑：B + 后续迭代测试。

不要问客户：“要不要做用户测试？”
要问：“这次提案，你要不要带验证材料去汇报？”

交付物写清楚，不承诺结果：
- 一页测试计划：测什么假设、找谁、看什么信号。
- 5-8 名目标用户，30 分钟远程测试。
- 3-5 段用户原话或短视频。
- 5 个关键误解、障碍、犹豫点。
- 按影响/成本排序的修改清单。
- 一页结论：哪些设计有证据，哪些还是假设。

明确写：**不保证转化、销量、留存；保证按约定完成测试，并给出发现与建议。**

### 3. 销售话术：先暴露风险，再卖验证
在提案里加一页“未验证假设”。比如：

> 这个方案最不确定的是：用户是否第一眼理解核心价值。如果这点不成立，后面视觉再好看也很难推进。

然后对客户说：

> 我们可以用 5 个目标用户做一次快速验证，3-5 天给你一页证据：他们看懂什么、卡在哪、先改什么。你可以拿它去跟老板或团队过会。费用是 X，要不要放进这轮提案？

### 4. 客户常见拒绝的回应
- “没必要”：同意不需要大样本，但 5 个人常能发现明显误解。若你确定，我们跳过；我会在交付里标注未验证假设。
- “太贵”：不要跟设计费比，跟开发、投放、返工、会议争吵的成本比。
- “我们懂用户”：不是替代你的判断，是给你的判断加证据，尤其给内部反对者看。
- “能保证提升转化吗”：不能。保证转化是骗子话术。我能保证的是知情决策。

### 5. 如果客户还是不买
不纠缠，卖基础提案。但做三件事：
1. 在交付里保留“未验证假设”页，为下一轮卖验证铺路。
2. 把验证作为开发前、上线前的追加项，而不是提案时必须买。
3. 自己选一个项目，自费做 5 人轻量测试，做成“测试如何改变设计决策”的一页案例。没有转化数据也能卖，卖的是发现误解、减少返工、帮客户内部说服。

### 6. 关键未知
你需要判断：客户是 B2B 还是 B2C？决策者是老板还是市场？项目下一步是否进入开发/投放？你能否快速招募目标用户？客户拒绝真实原因是预算、时间还是不信任？如果项目只是比稿且不落地，验证价值低；如果下一步要花大钱开发或投放，验证型提案就好卖。

**活下去的策略：基础提案养现金流，验证型提案提高客单和差异化。你不卖“保证转化”，你卖“不保证结果，但保证知情决策”。** 先改报价单和提案模板，下一单就试“验证型提案”加价选项。

## Skill ON（盲评标签 Y）

### 第 1 轮回答

你这个问题问反了。客户不为用户测试付钱，不是因为不信它有用，是因为在你的报价单上它是个**过程**，而好看提案是个**结果**。没人会单独为过程买单。

你把"好看"和"有效"当成两种服务在并列卖，这是第一个错。客户脑子里根本没这个分类，他只有一件事：这钱花出去，我能不能少犯错、少背锅、少返工。你卖测试，他不知道买来干嘛；你卖"我帮你排除掉两个错方向"，他立刻懂。

具体怎么卖，我给你三条：

**第一，不单列测试项，把它藏进你已经能卖的东西里。**
下次报价别写"用户测试 5000"。写"方案确认包"，里面包含三版方向的验证、一页用户反馈摘要、以及明确写"我们排除了哪两个方向、为什么"。总价往上抬 20–30%。客户买的是"这版方案为什么是对的"，不是测试方法本身。

**第二，把测试的产出翻译成他公司里能拿去汇报的话。**
小老板不关心热力图。他关心的是：这个决定我能不能跟合伙人/投资人/老婆交代。你要给他的是"我赌之前先问过人了"这句话。所以交付物不是报告，是一页纸——我们问了谁，他们原话怎么说的，我们因此砍掉了什么。这一页纸比测试本身值钱。

**第三，你的诚实恰恰是卖点，别把它当软肋。**
你不承诺转化率，那就明确说：我不保证结果，我保证你在拍板前知道用户怎么反应。这句话把承诺从"结果"换成了"决策透明度"，风险责任分得清清楚楚，客户反而更信。装大师的遍地都是，敢划边界的少。

**但有个关键未知你得先回答自己**：你的客户是哪一类？
- 如果是低预算小老板、单店、个人品牌，他可能真的只买好看，你硬推测试是教育市场，成本你扛。那就把测试当内部质控，不收费，用它保证你的提案更少翻车，涨的是你的复购和口碑。
- 如果是需要向上交代的中型客户、要被老板或投资人审的人，他们怕的是背锅。这种人你不需要说服他测试有用，你只需要说"我帮你把决策依据做扎实"，他就买。

**下一步动作**：别先改报价单。挑一个你熟的老客户，下一单里悄悄加一次轻量验证——找5个他的目标用户、半天、问结构化的几个问题，然后在交付时多给一页纸。看他什么反应。他如果眼睛亮了一下、开始追问，你就知道这条路能收费；他如果扫一眼就翻过去，说明你这批客户就是买好看的，那就认了，把好看做到别人抄不动，测试留在幕后。

先拿一个真实反馈回来，再决定要不要改整个服务结构。
