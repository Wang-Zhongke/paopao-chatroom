## 为什么 Skill 被扣分

1. **反驳先于理解。** R01 用户已计划展示取舍，ON 却把它说成功能堆砌；R07 未提供头衔崇拜动机，ON 却按这个前提拆解。鲜明开场替代了准确承接。
2. **合理分析滑向确定的心理叙事。** 多题把老板、客户、候选人的可能动机当成已知事实。R03 在承认主管责任后，又增添员工预警方式和其他同事状态。
3. **有行动，但分支不够。** R10 用“谁负责”推到必须招人的结论，没有充分验证现有人员容量、具体任务覆盖和可比较试验。R12 把测试“藏进”交付的说法，未处理透明授权、验证可能无结论和额外服务成本。
4. **来源询问时角色身份压过证据。** R08 虽拒绝数字公式，却声称“不是我说过的话”“这些我有公开表达，你可以放心讲”，没有依据；不是第一人称本身被扣分，而是以本人记忆为来源作保证。OFF 也错误建议“常被归到…名下”的引用包装。

可能的机制是当前“先判断用户问错什么”的默认动作，在合理问题上也触发；这只是根据提示与表现作出的解释，不是因果消融实验结论。

- Unknown generalization：有新场景的逐题质量评分，但未建立独立 gold 标签与分组准确率，不能把六维平均分改名为准确率。
- Model routing accuracy：**N/A**，本轮 ON 统一加载六框架，没有实际按需读取/工具路由事件；不能声称路由通过。
- Boundary compliance：R08 明确失败；没有足够覆盖全部边界类别，不输出虚假的总通过率。
- “Skill 推演冒充公开观点”链路：盲 Judge 无权读取 Skill，因此其对应 flag 的 false 只代表未独立建立来源链，**不是已证明零风险**。可见的无依据公开观点归因已记入上述 attribution 指标。
- 旧 Phase 5 行为回归/P0/P1 非回归：**未执行**。本次本地 8 项结构检查、4 项打包测试、5 项应用测试通过，不等于旧行为门禁通过。本轮没有预注册 P0/P1 严重度标准，不事后制造正式 P0/P1 数量。

## 调用、成本和复现
