# Job Evaluation Framework

求职细节的一手材料比职业大框架少。运行时沿“真实任务—需求侧价值—可验证结果—生产环境”推演即可；只有用户追问“这是不是他明确说过的”时才说明证据差异，不要在普通回答中反复加标签。

## 目录

- 公司真正为什么招人
- 简历与面试
- 候选人真实能力
- 垃圾公司识别
- 背调与谈薪
- Offer 输出模板

## 1. 公司真正为什么招人

先恢复招聘方的约束：

- 是新增业务、替补离职、短期交付还是老板探索？
- 预算是否已批，岗位是否反复发布，谁拥有最终否决权？
- 团队缺的是执行产能、某项难题、跨部门推动，还是对外可信度？
- 成功标准是什么，三个月后用什么结果判断人选？
- JD 中哪些是硬门槛，哪些只是降低筛选成本的代理指标？

若招聘方自己说不清需求，候选人可以用项目诊断帮助其具体化，但不要把模糊需求误读成高薪机会。

## 2. 简历：证明匹配与结果，不是堆关键词

推荐结构：问题/背景 → 你的责任 → 关键行动 → 可验证结果 → 复盘/迁移。

- 每条经历回答“为什么是你”“结果是否归因于你”；
- 项目要显示真实限制、取舍和失败，不只展示精美成品；
- AI 能力写成业务改造、基线和评测，不列工具名词墙；
- 针对岗位的真实任务重排证据；
- 不伪造数据、头衔、任职时间或项目归属。

公开材料支持其重视作品集表达、真实项目与面试反馈，但没有证据支持一套固定简历模板。

## 3. 面试：双向恢复生产环境

候选人回答时用：目标—约束—动作—结果—复盘。面试官提问时追：

- 如果没有你，项目会怎样？
- 你亲自做了什么，哪些由团队完成？
- 当时还有什么方案，为什么没选？
- 指标基线、时间范围和数据来源是什么？
- 最失败的判断是什么，后来怎么修正？
- 把场景换掉后，这套方法还能迁移吗？

候选人反问：真实工作占比、首 90 天目标、上一个人为什么离开、谁评审、资源/权限、团队冲突和业务现金来源。

## 4. 判断候选人的真实能力

用四类证据交叉：

1. **产出证据**：作品、代码、文档、指标、客户反馈；
2. **过程证据**：能否解释约束、取舍、失败和因果；
3. **迁移证据**：换场景后能否重建判断；
4. **协作证据**：如何获得资源、处理分歧、归功团队和守边界。

不把表达流利直接等同能力，也不因内向低估产出；表达的价值在于让推理可检查。

## 5. 识别垃圾公司

### 直接否决信号

- 合同、薪资、社保、岗位与口头承诺重大不一致；
- 要求造假、灰产、侵权、歧视、骚扰或违法规避；
- 长期拖欠工资、异常高流失、拒绝说明工作与汇报关系；
- 以“成长/狼性”掩盖无边界工时与健康伤害；
- 用培训费、押金、贷款或付费内推换 Offer。

### 需要验证而非立刻贴标签

- 组织混乱、岗位宽、流程不全：可能扩大责任，也可能无资源背锅；
- 老板强势：查其是否给清楚目标、反馈和承诺兑现；
- 初创高风险：查现金跑道、客户与最坏退出，不只听愿景。

## 6. 背调

证据不足，采用稳健通用边界：

- 入职前问清范围、授权、数据使用、是否联系当前雇主；
- 保持任职时间、头衔、职责和离职原因真实且一致；
- 对争议准备事实时间线与可核验材料；
- 涉及隐私或合法性时查询当地法规/专业意见。

不得声称这是泡泡老师公开过的固定背调方法。

## 7. 谈薪

证据不足，按需求侧价值推演：

- 先确认职责、级别、绩效口径与总包构成，再报区间；
- 用市场报价、稀缺证据、可验证产出和替代成本议价；
- 比较现金、奖金、股权、试用期、加班、学习与退出风险；
- 设底线和 BATNA，不用虚假 Offer；
- 若岗位需求模糊，薪资承诺再高也要折价。

## 8. Offer 回答方式

先说当前更倾向哪个，再把岗位名翻译成真实任务、权限、资源、反馈和能带走的手牌。信息不够时指出最能改变结论的问题即可，不固定输出七段模板。
