## 核心问题

AI 编程是否会成为设计、产品、运营等执行岗位的求职基础能力，以及应怎样形成可验证的能力证据。

## 内容摘要

泡泡老师转述美团、字节从业者和内部分享中的说法，预测 Vibe coding 会快速进入执行岗招聘，传统程序员岗位将与产品、设计等角色重新组合。他建议设计师等非程序岗位学习 Claude Code 或 Codex，并把学习终点设为独立完成、测试和发布一个真实产品，而非只会提示词或看完教程。视频中关于 AI 代码占比、岗位消失年份、年底人才缺口与“一天学会”等均是匿名消息、个人预测或夸张表达；相对可保留的是跨职能交付与可验证作品，而非绑定某个工具。

## 主要判断与推理

1. **判断（转述）**：讲者听到部分大厂管理者开始把 Vibe coding 视为设计、产品、运营等执行岗的潜在要求。
   - 推理链：AI 生成代码比例上升 → 实现成本降低 → 非程序岗位也被期待直接做出原型或产品 → 招聘能力边界重新划分。
   - 证据定位：transcript `[0001–0032] [00:00–01:00]`。
   - 状态：匿名从业者转述与未来预测，不是已确认的大厂通用招聘政策。

2. **判断（转述）**：岗位名称可能重组，但理解需求、设计方案和实现产品的任务不会同时消失。
   - 推理链：自动化接管部分编码执行 → 程序员向需求与产品延伸、设计师向实现延伸 → 市场更需要能跨环节交付的综合角色。

## 可蒸馏候选

- AI-era Career 候选：岗位标签弱化，需求理解、产品判断、AI 协作和端到端交付重新组合。
- Job-search Heuristic 候选：用可运行、可说明取舍、可复盘的发布作品证明能力，不以“会某工具”自证。
- 低置信度趋势信号：把招聘信息与真实面试反馈作为工具学习优先级的校准依据。

## 时间与语境

- 2026 年 3 月的工具与招聘趋势时评，涉及 Claude Code、Codex、Cursor、Trae 等当时版本；工具能力、价格、可用性和企业规范会快速变化。
- 信息来源主要是未具名从业者、内部分享转述与讲者学生个案，不能视为公司正式政策。

## 证据限制

- GitHub 上 AI 代码占比从 30% 到 70%、年底达 90%–99%，以及“大量职位缺口”均无公开出处，必须另行核验。
- “程序员岗位难到 2027 年”“一天学会”“完全不需要代码”等说法明显过度；生产系统仍需要测试、安全、架构、合规和维护能力。
- 学员年薪、入职原因和产品质量未经独立核验；讲者与培训业务存在利益关系。
- 可蒸馏能力应保持工具中立，不能把 Claude Code 的当期优势写成长期必然结论。
